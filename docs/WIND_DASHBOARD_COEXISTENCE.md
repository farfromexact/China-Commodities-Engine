# Trading Desk 共存采集（2026-11-12）

用户已授权：Trading Desk 开着时仍可采集，股票与商品采集之间串行并限速。
原先根据 8765 端口一律阻止采集是软件保护策略，不是已证实的 Wind 强制限制。

## 模式与接口

每日配置新增 `allow_dashboard`（默认 false）。设置 true 后，日常采集不会因为
Trading Desk 端口监听就等待。`request_interval_seconds` 默认为 2，商品入口最小为 0.2 秒，
在实际采集子进程中保证每次原生请求结束后留出间隔；不修改已审核股票 profile 的哈希。

股票共存模式使用 `arm --login-confirmed --dashboard-coexistence --minutes 60`，
而不是声称拥有包含看板在内的独占窗口。`tick` 要求就绪文件与配置模式一致。
旧独占模式与 `--exclusive-window` 仍兼容；临时文件不能跨主机或无限期使用。
商品仍使用一次性的 `--signal-login`；连接失败沿用 15 分钟退避，不自动重复登录。

两个引擎的实际 SDK 子进程共用同一 OS 用户临时目录中的
`wind-engines-<uid>/collection-v1.lock`（Windows 为 `wind-engines-user`）。
锁由原生工作进程持有；崩溃由 OS 释放，不删除锁文件来抢占。
商品拿不到锁返回 `waiting_collector` 并保留未消费登录通知；股票返回等待状态。
统一启动器仍按股票、商品顺序调用，不同时启动两个生产采集任务。

锁协议代码位于两库 `wind_coordination.py`，锁路径与获取/释放协议保持一致。
11月12日用户要求本次商品采集显式使用0.2秒间隔；仅降低商品端配置下限，
股票端节流和两个入口的默认2秒不变。请求仍串行，0.2秒为请求完成后的最小间隔，
不保证Wind每秒完成5次请求；遇限流/错误沿用停止及缓存恢复，不绕过供应商限制。
锁覆盖股票 WindSession、商品每日 worker 和本次商品 probe；没有将旧历史 backfill
脚本改造成统一队列，不要同时另跑这些旧工具。锁不协调其他电脑或其他 OS 用户。

不关闭、重启、注销 Wind 或 Trading Desk，不取消看板订阅，不恢复远端旧取数。
SDK 错误、超时、数据校验失败仍停止当前任务/退避，保留缓存，不伪造成功状态。

## 小样本验收

股票：`scripts/probe_wind_coexistence.py --date 2026-11-11 --login-confirmed`，
固定 3 只股票单日 OHLC，校验代码、源日期、形状、有限正数与 OHLC 顺序。
商品：`scripts/probe_wind.py --date 2026-11-11 --codes AU2612.SHF,SC2612.INE,M2701.DCE --allow-dashboard`。
两者仅保留诊断结果，不发布生产数据。必须在看板已连接时，顺序运行并比较前后
`/api/state` 的连接、重启次数、HTTP 响应和处理延迟。

非交易时段的小样本通过不代表交易高峰或全市场大批量性能已验证，也不替代 Windows 实机验收。
