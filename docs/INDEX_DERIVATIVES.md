# 股指衍生品：报告价值与请求量

`START_WIND.cmd` / `START_WIND.command` / `scripts/run_wind_daily.py` 共用同一入口。
只有用户明确启动后才连接 Wind、采集、校验并自动提交推送数据；不增加定时任务、常驻进程或远端触发。
商品期权继续使用 `core_v1`，不联动其他仓库。

## 默认 report_v1

IF、IH、IC、IM 期货覆盖目标日全部合约。IO、HO、MO 的完整目录只用作选样元数据，不默认查询全目录报价。

- 最近两个未到期月份，另补主力期指对应月份（不在前两月时），最多三个月。
- 每月最多七个执行价，每个同时采认购/认沽；优先 ATM、25/10 Delta 两翼，再补已有样本持仓集中的两个执行价，余量由附近执行价补齐。
- 优先参考先前已验证样本 Delta；与目标偏差超过 0.08 时，用现金指数及先前样本 IV 选择执行价。没有先前 IV 时采用明确标注的25%波动率选样假设，不冒充实际 IV。
- 选样参考现金价格，不冒充平价推导的远期。实际采样日期、执行价、波动率来源、选样方法和预算写入 `collection_plans`。

通常每品种28个、三品种合计84个合约；最多每品种42个、合计126个。
相对2026-11-13实测全目录760个合约，盘中逐合约分钟请求通常减少约89%，上限样本减少约83%；这是请求数量比较，不是实机耗时保证。
日终按多合约、单指标分批 WSD，每批最多200个；通常84个样本的期权报价共15次 WSD，另有期货、目录、现金市场和盘口请求。

完整链只在忽略的 `tmp/wind-daily/config.json` 显式设置 `"index_options_scope": "full_chain_v2"` 后启用；默认是 `report_v1`。
已有合格完整链可满足报告模式，不为改成样本重复采集。

## 分析与历史比较

方法参考 [China-Options-Engine](https://github.com/farfromexact/China-Options-Engine) 的 `engine.py` / `futures_link.py`，版本 `a4c16a18d16d039a30e9c162950096c9333a0a49`。
迁入分析和报告结构，采集统一走官方 WindPy，不迁入公共行情爬取或自动调度。

结算价无正值时回退正收盘价；按认购认沽平价推导同到期远期，再用 Black-76 重算 IV、Delta、Gamma。
无风险利率是明确的固定1.5%假设，到期日来自 Wind 目录。未知行权方式、已到期或IV不可解时，Greeks留空。
汇总 ATM IV、10/25 Delta wings、RR25、BF25、PCR及最多五个Gamma节点；两翼采用最近观察Delta，并记录实际Delta、执行价和目标距离，不冒充插值曲面。

**样本 PCR/OI/Gamma 只代表所选执行价**，`pcr_scope`、`gamma_scope` 明确标注，不代表全市场；Gamma不推断做市商方向。
期指另有主力/下一合约、期限结构、现金基差和同月份期权远期差。基差未作分红/融资成本调整，IC不以MO/IO冒充直接股指期权。

历史保留最近60个合格交易日摘要；严格1/3/5/20日比较要求连续验证日期、同价格和采样模式。
期权按同月份代码连接；样本执行价集合变化时，PCR/成交/持仓合计变化留空，不把选样变化当资金迁移。
持仓增减只比较相邻交易日同一合约；首次缺前日快照时留空。

## 盘口与ETF限制

日终盘口仅针对样本，每批最多50个合约进行一次性WSQ快照，不订阅，不复用旧启动的盘口缓存。
响应 `Times` 不是行情日期；保存请求时间、`RT_DATE`、`RT_TIME`和原值。实测供应商时钟出现过收盘后时间，因此 `time_verified=false`，不作为15点收盘盘口、不进入结算价分析、不标成可执行报价。
补采历史日时不以当前WSQ冒充历史盘口。历史WST仅完成单合约小窗口探测，未接入大规模回填。
盘口错误记录partial，不阻塞合格EOD。盘中遵守启动减五分钟并对齐五分钟边界，不混入较新的WSQ或旧持仓量。

现金指数：000016/000300/000905/000852；ETF：510050/510300/510500/512100。
ETF读取当日和前一交易日 `unit_total`，保留 `total_shares_raw`、`share_change_raw`；`share_change_pct`单位是小数。
单位仍待元数据确认：`share_unit_verified=false`，规范化份额、人民币申赎估算均留空；不使用日期口径不明的 `netasset_total`推导当日份额。

## 输出与升级

- `data/index_derivatives/latest.json`、`snapshots/YYYY-MM-DD.json`：实际所选范围的逐合约EOD及分析。
- `radar_latest.json`、`radar_history.json`：报告摘要与严格历史比较。
- `books/latest.json`：独立盘口观测；`intraday/`：同样按样本预算查询的延迟分钟快照，缺失明确记录。
- 统一报告和Chat分片提供这些文件的入口。

旧schema 1/core_v1保持可读；同日升级前原样保存到 `legacy_core/snapshots/`。
升级日期沿用本地起始日期规则，仍需用户明确启动，不导入另一仓库未核验的历史盘口。
2026-11-14已通过Windows EOD实机补采、计算、校验与推送：11月11—13日每日16个股指期货、84个期权样本。Windows盘中及Mac新入口仍未整轮验收，盘口时钟语义及ETF单位限制继续保留。
国债期货与回购资金面使用独立模块，见 [利率模块](RATES.md)，不混入股指样本或商品夜盘。
